# 故障排除

本章列出症状及其解决方法。网页安装器的**选择症状**步骤在屏幕上显示了大部分安装相关条目。

## 安装

这些行也适用于 `rfoundry` 命令行。

| 问题 | 原因与解决方法 |
|---|---|
| “no radio bootloader found” | 电台不在引导程序中，或线缆只能充电。关闭电台，按住其引导程序按键（[电台参考](23-radios.md)中你电台的“Installing”章节），然后开机。屏幕保持黑屏。换一个 USB 端口或线缆试试。在 Windows 上，安装引导程序的驱动（[步骤](02-installing.md#windows-the-bootloader-driver)） |
| “access denied” | 在 Linux 上，添加 rfoundry 打印的 udev 规则，然后拔下电台再插上。在 Windows 上，用 Zadig 安装引导程序的驱动（[步骤](02-installing.md#windows-the-bootloader-driver)） |
| “the bootloader is busy” | 另一个程序打开了它，例如 CPS 或启用 USB 直通的虚拟机。关闭它，然后拔下电台再插上 |
| 网页安装器说电台的端口或 USB 连接正在使用中 | 关闭正在使用电台的其他程序或浏览器标签页（CPS、qdmr、热点主机、第二个安装器标签页），然后重试。在 Windows 上，安装引导程序的驱动（[步骤](02-installing.md#windows-the-bootloader-driver)）。在 Linux 上，给你的用户授予该设备的访问权限 |
| 网页安装器无法使用某个固件文件 | 安装器会说明原因。见[安装器无法使用文件时](#when-the-installer-cant-use-a-file) |
| 备份或安装中断后，电台停留在更新模式，电源开关不起作用 | 见[停留在更新模式的电台](#a-radio-left-in-update-mode) |
| 刷写后屏幕保持黑屏 | 电台仍在其引导程序中。不按任何键，关机再开机 |
| 每次开机都是白色背光屏幕和常亮红色 LED，电台始终无法启动 | 由于固件缺失或不完整，电台处于其工厂更新模式。其他部分都没有损坏。用网页安装器重新安装。[电台参考](23-radios.md)中你电台的“Installing”章节说明这是否适用 |
| “准备电台失败”，或电台在编程线上没有响应 | 把线缆插头完全插入后重试，或使用带 FTDI、CP210x 或 PL2303 芯片的线缆。如果仍然失败，见[线缆无法准备电台时](#when-the-cable-cant-prepare-the-radio) |
| 网页安装器报告“检测到线缆问题” | 故障在编程线，不在电台。见[线缆问题](#cable-problems) |
| 刷写中途停止 | 让电台进入引导程序，再次运行同样的安装。安装器从不擦除引导程序 |

### 安装器无法使用文件时

安装器无法使用某个固件文件时，它会说明发现了什么以及该怎么做：

| 它显示 | 请这样做 |
|---|---|
| 此文件属于另一款电台 | 选择你电台的文件，或为该文件所属的电台打开安装器 |
| 这不是厂商的固件文件 | 选择厂商的文件。其他开源固件项目的构建不能使用 |
| 此文件不属于（你的电台） | 该文件属于另一型号，或是修改过的构建。选择你电台的厂商文件 |
| 此版本的编解码器尚不支持 | 选择消息下方列出的受支持文件之一，或发送该文件，以便添加该版本 |
| 文件已损坏或不完整 | 重新下载文件 |
| 电台编程工具无法使用此文件 | 文件没有问题。安装器会报告该故障，或说明如何报告。你可以发送该文件提供帮助 |

不受编解码器支持的版本仍可提供引导程序密钥；通知会说明这一点。你也可以在没有可用文件的情况下继续。安装器随后保留电台中已有的编解码器，
并在写入前说明 DMR 语音依赖该编解码器。

**技术细节**显示确切的消息。只有当文件是厂商的固件文件时，安装器才提出发送它，并且只在你点击后才发送。自动错误报告会列出文件（名称、大小和校验和），
但从不包含其内容。

### 停留在更新模式的电台

因拔线或关闭页面而中断的备份或安装，可能让电台停留在其加载程序中（更新模式）。此时电源开关可能不起作用。

1. 在安装器的第一页，选择**电台停留在更新模式**，然后选择电台。
2. 对于安装器通过线缆编程的电台，还要选择线缆。安装器把电台重启到正常模式。对于其他电台，页面会说明如何手动重启电台。

如果加载程序没有应答，关机再开机。如果电源开关不起作用，取下电池几秒钟。

当你为其他任务连接而加载程序已在运行时，连接步骤会在**继续**旁边提供**重启电台**。**备份**之后，**重启电台**会以一个完成屏幕结束任务，
该屏幕提供**安装**或**完成**，电台运行 RadioFoundry 时还提供**更新**。

### 线缆问题

带 CH340 芯片的编程线在备份和安装时可能不可靠。如果失败，请使用带 FTDI、CP210x 或 PL2303 芯片的线缆。安装器看到 CH340 线缆时会警告你。

连接步骤能区分故障线缆和不应答的电台，并指出问题：

| 安装器显示 | 它发现了什么 |
|---|---|
| 线缆不断送来无人请求的数据 | 线路从不安静，因此安装器听不到电台。**仍然继续**用同一根线缆继续 |
| 线缆与电脑断开了连接 | 页面使用线缆时，线缆离开了电脑的 USB |
| 线缆不再接收电脑发来的数据 | 线缆的适配器或其驱动停止发送。页面每次打开线缆时都会检查这一点。有些适配器会保持这种状态，直到你把它们拔下 |
| 电台没有收到本页面的任何应答 | 电台开机时的问候已传过来，但页面发送的内容都没有到达电台，电台已正常启动。该线缆只传送来自电台的数据。这样的线缆还可能拉住电台的 PTT 线：把它从电台上拔下 |

要解决以上任一问题：

1. 从电脑上拔下线缆，等几秒钟。
2. 把线缆直接插入电脑，不要经过集线器。
3. 把插头完全插入电台。
4. 选择**重试**。

如果问题再次出现，换一根更好的线缆，最好是带 FTDI 芯片的。

安装器等待电台开机时，会显示线缆已传送了多少数据，以字节和线路错误计。如果你关机再开机时计数一直为零，说明插头没有接触好或线缆有故障。
如果计数在变化但安装器找不到电台，说明线缆读取电台不良：把插头完全插入，或使用带其他芯片的线缆。

### 线缆无法准备电台时

通过编程线安装的电台会先在其内存中获得一个小加载程序。电台开机时，只等待安装器应答约 1/20 秒，而有些线缆和 USB 集线器比这更慢。
因此安装器在电台启动时持续发送应答。关闭电台，选择**电台已关闭**，然后开启电台。已运行 RadioFoundry 的电台会跳过这一步。

如果加载失败（“准备电台失败”）、电台改为正常启动，或电台始终不应答，安装器会提供**使用工厂更新模式**。这是电台自己的更新模式，
你在开机时按住按键进入（[电台参考](23-radios.md)中你电台的“Installing”章节）。安装器这样无法从电台读取任何内容，因此不做备份，
语音编解码器来自文件：原厂固件文件，或在安装器不知道该电台的原厂文件时，电台的程序存储器备份。安装器中的故障排除提供同样的途径
（**在工厂更新模式下重新安装**），恢复也使用它。

## 命令行安装（高级）

网页安装器在屏幕上显示这些问题，并引导你解决。这些行适用于用 `rfoundry` 安装的情况，包括使用安装器的
[手动安装套件](02-installing.md#install-from-the-command-line-with-a-kit)。

| 问题 | 原因与解决方法 |
|---|---|
| “unknown stock file ... not a supported codec source” | rfoundry 按 SHA-256 哈希识别原厂固件文件。下载[电台参考](23-radios.md)中你电台的“Installing”章节所列的确切文件 |
| “... is an official Baofeng/TYT firmware file, not a RadioFoundry image” | 你把原厂固件文件当作镜像提供了。提供 RadioFoundry 镜像（或 `--release`），并用 `--stock` 提供原厂固件文件 |
| “rfoundry can't tell whether the radio holds the codec” | 用 RadioFoundry 启动电台并运行 `rfoundry probe`，或提供 `--stock`，让 rfoundry 写入编解码器 |
| “no libusb found”（从源码运行时） | 安装 libusb（`brew install libusb` 或 `apt install libusb-1.0-0`），或使用自带它的 rfoundry 可执行文件 |

## 无编解码器（“无编解码器：语音关闭”）

DMR 呼叫在屏幕上显示，但没有声音：电台没有可用的编解码器。再次运行网页安装器，并提供原厂固件文件。在终端中运行：

```sh
rfoundry flash --release latest --codec merge --stock STOCK.bin
```

## 日常使用

| 问题 | 原因与解决方法 |
|---|---|
| DMR 呼叫显示但没有声音，电台显示“无编解码器：语音关闭” | 电台没有可用的编解码器。见[无编解码器](#no-codec-no-codec-voice-off) |
| DMR 呼叫显示“其他通话组：不播放” | 该呼叫的通话组不是通话目标，不在收听列表中，也不是回复目标。按**监听**（数字监听），或把该通话组加入信道的接收组列表。鹦鹉台回放你自己的呼叫（源为你自己的 ID）时，与其他呼叫一样播放 |
| “已加密：不播放” | 该呼叫使用基本加密且电台没有匹配的密钥，或该呼叫使用电台无法播放的更强加密 |
| 发射时显示“电台频率中无 DMR ID” | 写入含你 DMR ID 的电台频率（[为电台编程](04-programming.md)） |
| “信道忙” | 有人正在该时隙上讲话。等待呼叫结束 |
| “中继台无应答” | 中继台没有响应。检查频率、色码、时隙以及你与中继台的距离 |
| FM 上没有声音 | 静噪关闭，或该信道需要亚音。按住**监听**打开静噪。用 **\***、**3** 检查亚音 |
| 按键不起作用，屏幕显示“按键已锁” | 长按 **\*** 解锁。检查**设置 > 按键锁 > 自动锁键** |
| “此处未使用” | 该键在此屏幕上没有功能 |
| “……：本版本无” | 该功能在此构建中已关闭 |
| 电台卡在热点屏幕上 | 有主机打开了串口。按 **OK**，或停止主机程序。要防止这种情况，关闭**设置 > 连接 > 允许热点** |
| 区域或信道自己变了 | 扫描正在运行（状态行中有 SCAN）。在主屏幕上按 **返回** |
| qdmr、rfoundry 或热点主机找不到电台的串口 | USB 处于网络模式。在**工具 > USB 网络**中切换回来，或关闭**设置 > 连接 > 启动时 USB 网络**并重启电台。调试链路和 MMDVM 也在 UDP 端口 3334 上应答（[USB 网络](15-usb-network.md#serial-tools-in-network-mode)） |
| 在网络模式下，电脑没有获得地址 | 电脑在 10 秒内没有设置好网卡时，电台会回到串口。检查电脑是否显示一个新的网卡，然后再次切换 |
| 写入电台频率失败，显示“电台拒绝写入电台频率” | 如果电台刚从原厂固件过来，再次选择**写入电台**。电台频率编辑器会提供**准备电台**，它从 RadioFoundry 保存设置的区域中擦除原厂固件的数据。不这样做，电台会拒绝每次写入，并在关机时忘记其设置。如果错误再次出现，使用**报告问题** |

## 设置无法保存

如果重启后设置恢复为默认值，且 qdmr 写入失败，说明电台在 RadioFoundry 保存设置的闪存区域中发现了另一个固件的数据。
RadioFoundry 不会擦除这些数据，因此你不会意外丢失它们。电台使用内存中的默认值运行。

开发者可以通过调试链路把该区域交给 RadioFoundry：

```sh
tools/rfoundry_debug.py storage info     # shows region=foreign
tools/rfoundry_debug.py storage claim --out ~/rfoundry-backup    # saves a copy of the area, then erases it
```

`storage claim` 在擦除任何内容前，把该区域的旧内容和校准副本保存到 `--out` 目录中的文件里。它拒绝保存到 git 工作树中。

在 Facebook 上的 [RadioFoundry 社区小组](https://www.facebook.com/groups/radiofoundry/)中提问。其他用户和开发者在那里回答问题、帮助安装并发布消息。

## 报告问题

### 从电台

在[项目代码库](https://github.com/radiofoundry/radiofoundry/issues/new/choose)中提交 issue。请包括：

- 固件版本（**设置 > 我的电台 > 关于**）。
- 电台型号。
- 你做了什么，你期望什么，以及发生了什么。
- 有帮助时附上截图。`tools/rfoundry_debug.py screenshot -o screen.png` 经 USB 保存一张截图。

如果电台自行重启，打开**设置 > 高级 > 崩溃日志**（[设置](17-settings.md#crash-log)），把其中的行复制到 issue 中。开发者用
`tools/rfoundry_debug.py crash` 获取完整记录。

对于接收的数字语音中的断续，请说明模式、信号强度，以及断续是贯穿整个呼叫，还是只在呼叫开始或结束时出现。

### 从网页安装器或电台频率编辑器

在 radiofoundry.org 上，页面会自行报告大多数错误：消息会说明这一点并给出一个参考编号。在消息下方的框中输入你当时在做什么，然后点击**发送详情**。
开发者会查看每一份报告。

要发送更多内容，或在报告功能关闭或被阻止时，使用**报告问题**。在网页安装器中，它位于每个失败之下、每个步骤下方的按钮栏中，以及**校验**步骤上。
页面看起来卡住且没有错误时，在重新加载之前使用它：重新加载会丢失页面的日志。

- 在网页安装器中，**报告问题**发送安装器做出的判断及其最后几个步骤。你可以添加一条消息、一个用于回复的电子邮件地址，以及它列出的文件
  （原厂固件文件、备份、从电台读取的固件）。备份包含你的信道、联系人和电台的校准：取消勾选即可不包含它。附加的文件和你的电子邮件地址会在 90 天内删除。
- 在错误消息下，**报告问题**还允许你描述当时在做什么并下载报告：一个 `.zip` 文件，含页面执行的步骤、错误以及你浏览器的详细信息。
  把它通过电子邮件发给开发者、附加到 GitHub issue，或在[社区小组](https://www.facebook.com/groups/radiofoundry/)中分享。如果问题在于读取或写入电台频率，
  勾选包含它的复选框。电台频率包含你的呼号、DMR ID 和联系人，因此除非你添加，否则不包含它。

开发者还可以打开浏览器的控制台（F12），每个错误及其详细信息都打印在那里。
