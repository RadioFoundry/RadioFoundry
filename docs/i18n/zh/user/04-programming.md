# 为电台编程

电台频率保存信道、区域、联系人、接收组列表、DMR ID 数据库和你的 DMR ID。用项目网站
[radiofoundry.org](https://radiofoundry.org/codeplug/index.html) 上的**电台频率编辑器**编辑它。
编辑器在基于 Chromium 的浏览器（Chrome、Edge、Opera）中运行，无需安装任何东西，可通过 USB 或编程线用于每款 RadioFoundry
电台。免费电台频率编辑器 qdmr 是另一种选择。

| 程序 | 运行于 | 用途 |
|---|---|---|
| 电台频率编辑器 | 浏览器中 | 本页的全部内容。这是推荐方式 |
| [qdmr](https://github.com/hmatuschek/qdmr) | Windows、macOS、Linux | 你已有的 qdmr 电台频率，以及脚本。需要 qdmr 的驱动能访问的电台（[qdmr](#programming-with-qdmr)） |
| `tools/cps_client.py` 和 TFTP | 终端 | 原始备份和脚本（[备份](#backups)） |

它们都使用相同的电台频率格式和电台自带的电台频率接口，因此一个程序写入的电台频率可被其他程序读回。
各电台如何连接以进行编程，见[电台参考](23-radios.md#programming)。

## 电台频率编辑器

在网站菜单中打开**电台频率编辑器**。它从浏览器读写电台。不会向服务器发送任何内容：文件、电台频率和你的 RadioID API
密钥都留在你的电脑上。

### 读取和写入电台

1. 在 RadioFoundry 运行时打开电台并连接：有 USB 的电台用 USB 线，否则用编程线。电台必须处于 USB 串口模式，
   而不是 USB 网络模式。
2. 选择**从电台读取**。浏览器列出电台的 USB 端口和所有编程线；选择电台的那个。编辑器根据端口判断是两者中的哪一个。

   读取电台的 DMR ID 数据库需要 20 秒或更久时（通过编程线传输数兆字节），编辑器会先说明所需时间，并询问是否也读取它。
   除非你要编辑数据库或把它保存在文件中，否则跳过；之后写入时，电台的数据库保持不变。**DMR ID 数据库**标签页可以稍后读取它。
3. 编辑电台频率。
4. 选择**写入电台**。编辑器把电台频率与电台中的进行比较，只写入发生变化的字节。它显示字节数和写入的大致耗时，
   然后写入并校验。电台无需重启即可载入新的电台频率。

读取后，如果该电台有更新的 RadioFoundry 发行版，编辑器会提示，并说明它在读写方面增加了什么（更快的传输、紧凑 ID 数据库）。
**更新固件**会在新标签页中打开[网页安装器的“更新”](02-installing.md#updating-radiofoundry)，并释放电台的端口，
以便安装器连接。更新期间，电台频率和设置保留在电台上。如果更新改变了电台的功率级别，在设置中、为 VFO 和为 APRS
选择的功率会回到电台的默认值：发射前请检查。电台频率中信道的功率会映射到最接近的新级别。

### 为多台电台编程

要把一份电台频率写入多台电台，依次写入每一台。每次写入前，编辑器会检查连接的是哪台电台。在编程线上换一台电台时，
编辑器会先读取新电台，再写入任何内容，因此写入是与该电台的电台频率比较，而不是与上一台的比较。

电台的名称、DMR ID 和启动文字与文件中的不同时，写入对话框会提供**保留此电台的名称、DMR ID 和启动文字**。
打开后，每台电台保留自己的这些信息，其余内容取自文件。编辑器会为下一台电台记住这一选择。

对刚从原厂固件转来的电台首次写入时，可能会要求你**准备电台**。原厂固件的数据仍在 RadioFoundry 保存设置的区域中，
在该区域被擦除之前，电台无法保存电台频率，也无法在关机后保留设置。[网页安装器](02-installing.md)在安装 RadioFoundry
时所做的备份之后，会自动完成这一步。备份中保存有该数据的副本。校准不会被改动。

存储芯片太小、放不下 RadioFoundry 设置区域的电台根本无法保存电台频率。编辑器会说明这一点，而不去读取它。
[电台参考](23-radios.md)列出了可能出现这种情况的型号。

**问题**标签页列出错误时（例如名称过长或频率无效），**写入电台**会被阻止。警告（例如频率超出电台的频段，
或 DMR 信道没有发射联系人）不会阻止写入。

浏览器无法访问处于 USB 网络模式的电台。此时选择**保存 > 用于 USB 网络**，并通过 TFTP 发送文件
（[USB 网络](15-usb-network.md#programming-over-the-network)）。

### 编辑

| 标签页 | 内容 |
|---|---|
| 电台 | DMR ID、电台名称（呼号）、启动文字、组呼和个呼的挂起时间、ARS 服务器、IP 网关 |
| 信道 | 所有信道。铅笔按钮打开完整表单：FM、DMR、扫描与功率、位置、单频中继 |
| 区域 | 区域及其信道 |
| 联系人 | 通话组和个呼联系人 |
| 接收组列表 | 每个信道收听的通话组 |
| DTMF 联系人、APRS | DTMF 联系人和 APRS 配置 |
| 系统 | 集群系统和其他数字模式的身份：站点、控制信道、信道计划和密钥。电台报告此类模式或电台频率中已有此类模式时显示（[数字模式与系统](#digital-modes-and-systems)） |
| DMR ID 数据库 | 不是联系人的 DMR ID 的名称，由 RadioID.net 构建（[DMR ID 数据库](#dmr-id-database-and-contacts-from-radioidnet)） |
| 问题 | 错误和警告，每项都带指向该记录的链接 |

在表格中，双击单元格或直接在其上输入即可就地编辑。点击列标题排序，在筛选框中输入以缩小行范围。要为多行设置同一字段，
选中这些行并选择**批量编辑**。批量编辑不适用于区域和接收列表，它们的成员在各自的对话框中编辑。**撤销**和**重做**
覆盖所有更改，包括导入。

**ARS 服务器**是电台向其注册的在线状态服务器的 DMR ID（[ARS](10-messages-and-signaling.md#registration-ars-and-location-lrrp)）。
**IP 网关**是把电脑的数据包转发到其他网络的电台的 DMR ID
（[USB 网络](15-usb-network.md#other-networks-through-a-gateway-radio)）。字段留空则保留电台自己的设置；输入 0 则关闭。
qdmr 没有这些设置，会保持电台上的值不变。其他写入电台整个存储器的编程软件也无法擦除它们：除非软件以 RadioFoundry
的格式写入，否则电台保留自己的设置。

页面把工作中的电台频率保存在浏览器中，因此关闭或刷新页面不会丢失编辑。**新建**会重新开始。

### 数字模式与系统

除 FM 和 DMR 外，信道还可以使用其他数字模式，例如集群系统。信道表单的**模式**列出所连接电台的固件报告的模式，
以及电台频率中已有的任何模式。此类模式的信道在**模式设置**下显示该模式的字段；集群信道从其系统取得频率。
固件不运行某信道模式的电台会显示该模式的简称，在该信道上不接收任何内容，也不发射。
[功能矩阵](../feature-matrix.md)列出哪些构建运行哪些模式。

**系统**标签页按类型添加系统。一个表单分节保存整个系统：

- 系统的身份；
- 它的控制信道：每个频率一行，从上到下依次尝试（**+** 添加一行，**−** 删除一行）；
- 本电台（**发射**、**本系统上的电台 ID**）；
- 呼叫、后备、密钥和无线共享。

很少有系统需要的节（站点与漫游、远程命令、固定信道计划）初始为折叠状态。点击标题展开该节。

每个系统有以下字段：

| 字段 | 含义 |
|---|---|
| 发射 | **从不**（仅收听）：电台跟随呼叫，但无论信道如何设置，都从不注册或发射。**是，先注册**。P25 还有**是，不注册**：PTT 立即请求话音信道 |
| 需要密钥 | 没有密钥就无法使用该系统。选中此项之前，密钥字段显示为灰色 |
| 无线共享区域/信道 | 区域共享发送系统的哪些内容：关闭、仅身份（默认；接收方必须已有该系统），或整个系统 |
| 本系统上的电台 ID | 你在该系统上的 ID。留空则使用该模式自己的 ID。从不共享。**发射**为**从不**时显示为灰色 |

电台频率中有密钥时，保存电台频率文件会询问是否包含它们。除非你选中**在此文件中包含密钥**，否则文件不包含密钥。
任何拿到含密钥文件的人都能读取密钥。CSV 和 qdmr 文件既不保存系统，也不保存信道模式。其他模式的信道会作为仅接收的
DMR 信道写入此类文件，从中读回时也是如此。要保留这些信道，请保留电台频率文件。

### P25 与 NXDN

在信道表单的**模式**中选择 **P25**、**P25 Trunking** 或 **NXDN**。要在电台上使用这些信道，见
[P25 信道](07-channels-zones-vfo.md#p25-channels)。通话组是信道的**发射联系人**（组联系人），接收组列表的作用与 DMR 相同。
信道上的**自身 ID**为该信道覆盖电台的 ID。

**P25 信道：**

| 字段 | 含义 |
|---|---|
| 静噪 | **普通**：该 NAC 上的所有呼叫。**选择性**：该通话组、对所有人的呼叫，以及对本电台的呼叫 |
| 接收 NAC | 要接收的网络接入码，3 位十六进制数。留空表示 293。F7E 接收所有 NAC |
| 发射 NAC | 要发送的接入码。留空表示与接收 NAC 相同（接收 NAC 为 F7E 时为 293） |

**NXDN 信道：**

| 字段 | 含义 |
|---|---|
| 速率 | 9600 bit/s（12.5 kHz）或 4800 bit/s（6.25 kHz） |
| 静噪 | **RAN**：该 RAN 上的所有呼叫。**选择性**：该组，以及对本电台的呼叫 |
| 接收 RAN | 要接收的无线接入号，0-63。0 接收所有 RAN |
| 发射 RAN | 要发送的 RAN。留空表示与接收 RAN 相同（接收 RAN 为 0 时为 1） |

**电台**标签页中各模式的字段：

| 字段 | 含义 |
|---|---|
| P25 单元 ID | 你的 P25 ID。留空表示使用 DMR ID |
| NXDN 单元 ID | 你的 NXDN ID，1-65519。留空时，DMR ID 不大于 65519 则使用 DMR ID，否则为 1 |

**P25 Trunking 系统**（**系统**标签页，类型 **P25 Trunking**）。新系统为仅收听：设置**发射**以注册和发射。

| 字段 | 含义 |
|---|---|
| WACN、系统 ID | 系统的身份，十六进制。留空表示任意 |
| 控制信道 NAC | 留空表示任意 |
| 控制信道 | 接收频率，单位 MHz，从上到下依次尝试。控制信道会公布发射频率、标识符和信道号时，它们可以保持为 0 |
| 跳过加密呼叫 | 不跟随加密呼叫的授权 |
| 呼叫后保持 | 呼叫结束后在话音信道上停留的秒数。0 立即回到控制信道 |
| 仅使用此处输入的信道计划（站点与漫游） | 忽略控制信道发送的计划 |
| 低于此值切换站点（站点与漫游） | 保存在电台频率中。电台不按信号强度切换站点 |

**站点**和**信道计划**（每个标识符的基准频率、间隔、发射偏移、带宽）是可选的。没有计划条目时，电台使用控制信道发送的计划。

**P25 集群信道：**选择**系统**和通话组（**发射联系人**）。**跟随系统的所有通话组**跟随对所有通话组的呼叫，
而不仅是该信道的通话组。**备用信道**保存在电台频率中；电台不使用它，而是继续搜索控制信道。集群信道没有自己的频率。

### 文件

**打开文件**接受以下文件：

- 由编辑器、`tools/cps_client.py read` 或 TFTP 读取保存的电台频率文件（`.bin`）。
- 网页安装器的备份（`.zip`）。
- qdmr 电台频率（`.yaml`）。
- CHIRP 保存的信道列表（`.csv`），或编辑器能读取的电台的 CHIRP 镜像（`.img`）。
- CSV 文件，每个文件一张表，或它们的 `.zip` 文件。
- 原厂固件的电台频率，限于编辑器能读取其格式的电台：安装器备份中的、电台数据闪存的转储，或制造商的 CPS 文件。
  [电台参考](23-radios.md#codeplug-files-from-the-original-firmware)列出了这些电台。

安装 RadioFoundry 时所做的备份仍保留原厂固件的电台频率，因为 RadioFoundry 以不同的布局保存自己的电台频率。
编辑器能识别该电台频率并转换它：信道、区域、联系人、接收组列表、DMR ID、电台名称和启动文字。之后它会列出省略的内容，
例如扫描列表和被缩短的名称。带有 A、B 两个列表的区域会变成两个区域：“名称 A”和“名称 B”。写入电台前请检查结果。
在你写入之前，电台上的电台频率保持原样。要使用编辑器无法打开的 CPS 文件，先用 qdmr 转换它（`dmrconf decode`），
再把结果作为 YAML 打开。

**保存**写入以下之一：

- 电台频率文件；
- qdmr 电台频率（`.yaml`）；
- CHIRP 信道列表（`.csv`）；
- 当前表格的 CSV，或所有表格的 CSV 文件组成的 `.zip` 文件；
- 用于 USB 网络模式的 `codeplug.bin`。

除 `codeplug.bin` 外，每次保存的文件名都以电台频率的名称加上日期和时间，例如 `codeplug-YYYY-MM-DD-HHMM.yaml`，
因此多次保存不会互相覆盖。打开带日期的文件再次保存时，保存会替换其中的日期和时间。

CSV 文件有带列名的表头行，并通过名称引用其他记录（信道的发射联系人、区域的信道）。要查看列，先保存一张表。
导入时先按编号、再按名称把行与现有记录匹配。文件可以只包含部分列；其他列保持原值。导入会删除文件中缺失的记录。
导入后，编辑器按行和列列出它无法接受的值。

qdmr 文件在一次更改中替换以下内容，因此一次**撤销**即可还原：信道、区域、联系人、DTMF 联系人、接收组列表、APRS 配置，
以及**电台**标签页中除 ARS 服务器和 IP 网关以外的设置。VFO 和 DMR ID 数据库保持不变。之后编辑器会列出更改或省略的内容，
例如扫描列表、加密密钥和被缩短的名称。保存为 qdmr YAML 时，会列出 qdmr 格式无法保存的内容：SFR 设置、qdmr
没有名称的功率级别，以及位置（位置会被舍入为 6 字符网格定位，约 5 公里）。**工具**页面也可在 qdmr YAML 与电台频率文件之间转换，
并把原厂固件的电台频率转换为其中任一格式。

CHIRP CSV 文件在一次更改中替换信道和区域，因此一次**撤销**即可还原。联系人、设置和 DMR ID 数据库保持不变。
信道取自文件中的 FM 和 NFM 行，按文件顺序编号，并放入以文件命名的区域中，每个区域 80 个信道。导入会保留偏移
（`+`、`-`、异频）、CTCSS 和 DCS 亚音（包括交叉模式）、带宽、跳过和功率。编辑器会列出省略的内容：其他模式的行（AM、DV、SSB）、
没有可用频率的行、电台无法保存的亚音，以及被缩短的名称。保存为 CHIRP CSV 时只写入 FM 信道，因为 CHIRP 没有 DMR。

CHIRP 镜像是一台电台的存储器内容，因此每种电台型号都需要自己的读取器，编辑器只读取它列出的型号。
它以与 CSV 文件相同的方式导入这些信道。对于其他电台，编辑器会说出它找到的型号，并请你在 CHIRP 中用
**File > Export to CSV** 导出信道。

### DMR ID 数据库与来自 RadioID.net 的联系人

**DMR ID 数据库**标签页根据 RadioID.net 上的注册用户构建数据库或个呼联系人。它从以下来源之一获取用户：

- **RadioID 用户文件**：从 RadioID.net 下载 `user.csv` 并打开。任意地区，任意大小。
- **从 RadioID.net 获取**：直接获取几个州或一个小国家的用户。RadioID.net 每次请求返回 200 个用户，
  因此适合最多几千个用户。你自己的 RadioID API 密钥是可选的。页面把密钥保存在本浏览器中，只发送给 RadioID.net。
  在 RadioID.net 允许来自本网站的请求之前，请求经由一个公共中继服务转发；密钥从不经由它发送。

然后选择：

- 地区（国家，以及州或省）；
- 呼号前缀和 DMR ID 范围；
- 每条记录显示的文字，由呼号、姓名、城市和州等字段组成；
- 文字长度（16 到 48 个字符）。

页面会预览记录，并显示数据库大小与电台可用空间的对比。**写入 ID 数据库**把数据库放入电台频率；**写入电台**随后发送它。
**添加为联系人**改为把这些用户添加为个呼联系人，并跳过已是联系人的 ID。编辑器在浏览器中记住这些选择。

联系人只留给你要呼叫的对象：你的通话组，以及少数你会个呼的人。电台频率最多保存 1024 个联系人，
每个联系人都是**联系人**中和通话目标选择器中的一行。其他人交给 ID 数据库命名：对于不是联系人的呼叫方，
电台显示数据库中其 ID 对应的名称。

RadioFoundry 读取**紧凑数据库**，其大小约为旧格式的一半，因此同样的空间可容纳约两倍的名称。从 RadioID.net
刷新后，写入只发送发生变化的部分。编辑器在写入时选择格式：

| 电台 | 编辑器的做法 |
|---|---|
| 能读取紧凑格式 | 写入紧凑格式。编辑器会提议转换旧格式的数据库（从电台读取或来自旧文件）：一次完整写入，之后写入量较小。如果你拒绝，12 小时后会再次提议 |
| 运行较旧的固件 | 写入旧格式。如果名称放不下，编辑器会说明省略了多少。更新固件可腾出空间 |
| 在紧凑数据库上安装了较旧的固件 | 电台不显示名称（从不显示错误的名称）。编辑器在下次写入电台时以旧格式重新写入数据库 |

TFTP（USB 网络模式）和其他 CPS 程序使用旧格式。

## 电台使用电台频率中的哪些内容

| 项目 | RadioFoundry 使用的字段 |
|---|---|
| 常规设置 | 你的 DMR ID。呼号（电台名称，8 个字符，作为通话者别名发送）。组呼和个呼的挂起时间（回复窗口）。ARS 服务器和 IP 网关（如已设置） |
| 信道（最多 1024 个） | 名称、接收和发射频率、模式（FM 或 DMR）、带宽、接收和发射亚音、功率、仅接收、色码、时隙、通话目标联系人、接收组列表（收听列表）、每信道 DMR ID、强制直通模式、发射超时（**电台默认**使用电台自己的设置，见[发射超时](08-fm.md#transmit-timeout)）、通话者别名、区域扫描跳过、允许 VOX、1750 Hz 突发音、无提示音、不省电 |
| 区域 | 名称和信道列表。没有区域时，电台显示一个包含所有信道的区域 |
| 联系人（最多 1024 个） | 名称、DMR ID 或通话组、个呼或组呼、时隙覆盖 |
| 接收组列表 | 每个信道收听的通话组 |
| 集群系统（最多 8 个） | **系统**标签页的所有字段，以及哪些信道是集群信道 |
| DMR ID 数据库 | 不是联系人的 DMR ID 的名称，显示在接收屏幕上 |
| VFO A | VFO 的频率和设置，在下次重启后读取 |
| 启动文字 | 启动画面上的两行 |

电台保持电台频率的其他所有部分不变（启动图像、DTMF 联系人等），因此编辑器和 qdmr 能读回它们写入的内容，
但 RadioFoundry 不使用这些部分。

你在电台上所做的更改（长按 **OK** 保存的信道、永久通话目标）会写入同一份电台频率，因此下次读取时可以看到。

电台频率不设置以下内容：

- 加密密钥（[加密](09-dmr.md#privacy)）。
- RadioFoundry 自己的设置（[设置](17-settings.md)）。电台把它们与电台频率分开保存，并忽略电台频率中的快捷键分配。
- 紧急和文本消息的格式。
- qdmr 中的 SFR 设置。电台频率编辑器在每个信道上设置它们。

## 用 qdmr 编程

电台通过兼容层使用 qdmr 开源固件驱动的协议，并以 qdmr 写入的布局保存电台频率。

1. 正常打开电台并连接 USB 线。电台显示为一个 USB 串口。
2. 在 qdmr 中从电台读取电台频率。qdmr 根据 RadioFoundry 报告的电台类型识别电台。
   [电台参考](23-radios.md#programming)列出了每款电台的类型和 qdmr 驱动。
3. 编辑电台频率并写入电台。
4. 写入后，电台重启并使用新的电台频率。

传输期间电台保持自己的屏幕。电台频率位于 qdmr 驱动无法写入的位置的电台，或没有 USB 端口的电台，需要其他途径。
[电台参考](23-radios.md#programming)会说明是哪些电台。

## 备份

更改电台频率之前，先读取并保存它：在编辑器中选择**保存 > 电台频率文件（.bin）**，或在 qdmr 中保存。原始备份也可以：
通过串口运行 `tools/cps_client.py read backup.bin` 和 `tools/cps_client.py write backup.bin`，或在 USB 网络模式下使用 TFTP
（[USB 网络](15-usb-network.md#programming-over-the-network)）。

要以 qdmr YAML 格式从网页安装器的备份（`.zip` 文件）中取出电台频率，运行 `tools/backup_codeplug.py BACKUP.zip -o DIR`。
它写出 RadioFoundry 的电台频率，以及备份中包含的原厂固件电台频率，每份各为一个 `.yaml` 文件和一个 `.dfu` 文件。
在电台频率编辑器或 qdmr 中打开 `.yaml` 文件。该工具需要 Python 3.11 或更高版本以及 qdmr 的 `dmrconf`（0.15 或更高版本），
且从不触碰电台。用它导入电台频率编辑器无法读取或只能部分读取的原厂固件电台频率。
[电台参考](23-radios.md#codeplug-files-from-the-original-firmware)说明哪些电台需要这样做。

要在安装时把电台频率从原厂固件迁移过来，见[从原厂固件迁移](18-moving-from-stock.md)。

## 限制与说明

- 电台的设置区域保存着其他固件的数据时，电台拒绝写入。见[设置未保存](20-troubleshooting.md#settings-are-not-kept)。
- 校准区域只接受对其自身字节的写入。不要用 CPS 编辑校准。
