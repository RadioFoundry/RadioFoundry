# 为电台编程

电台频率保存信道、区域、联系人、接收组列表、DMR ID 数据库和你的 DMR ID。请在项目网站 [radiofoundry.org](https://radiofoundry.org/codeplug/index.html) 上用**电台频率编辑器**编辑它。它运行在基于 Chromium 的浏览器（Chrome、Edge、Opera）中，无需安装任何东西，并可通过 USB 或编程线与每款 RadioFoundry 电台配合使用。免费电台频率编辑器 qdmr 是另一种选择。

| 程序 | 运行于 | 用途 |
|---|---|---|
| 电台频率编辑器 | 浏览器中 | 本页的全部内容。推荐方式 |
| [qdmr](https://github.com/hmatuschek/qdmr) | Windows、macOS、Linux | 你已有的 qdmr 电台频率，以及脚本化操作。需要 qdmr 驱动能访问的电台（[qdmr](#programming-with-qdmr)） |
| `tools/cps_client.py` 与 TFTP | 终端 | 原始备份与脚本（[备份](#backups)） |

它们都使用相同的电台频率格式和电台自带的电台频率接口，因此一个程序写入的电台频率可被其他程序读回。各电台的接线方式见[电台参考](23-radios.md#programming)。

## 电台频率编辑器

在站点菜单中选择**电台频率编辑器**。它从浏览器读写电台。不会向服务器发送任何内容：文件、电台频率和你的 RadioID API 密钥都留在你的电脑上。

### 读取和写入电台

1. 在 RadioFoundry 运行时打开电台并连接：有 USB 的电台用 USB 线，否则用编程线。电台必须处于 USB 串口模式，而不是 USB 网络模式。
2. 选择**从电台读取**。浏览器会列出电台的 USB 口和所有编程线；选择电台的那个。编辑器会从端口判断是哪一个。
   当读取电台的 DMR ID 数据库需要 20 秒或更久时（通过编程线传输数兆字节），编辑器会先说明所需时间，并询问是否也读取它。除非你要编辑该数据库或将其保存在文件中，否则跳过：写入时会保持电台的数据库不变。**DMR ID 数据库**标签页可稍后读取。
3. 编辑电台频率。
4. 选择**写入电台**。编辑器会比较电台频率与电台中的内容，只写入发生变化的字节。它显示字节数和大致耗时，然后写入并校验。电台无需重启即可载入新的电台频率。

读取后，编辑器会提示该电台是否有更新的 RadioFoundry 发行版，以及它在读写方面新增了什么（更快的传输、紧凑 ID 数据库）。**更新固件**会在新标签页中打开[网页安装器的“更新”](02-installing.md#updating-radiofoundry)，并释放电台端口，以便安装器连接。更新期间，电台频率和设置保留在电台上。

### 为多台电台编程

要把同一份电台频率写入多台电台，请依次写入每一台。每次写入前，编辑器会检查连接的是哪台电台。在编程线上换台后，会先重新读取，再写入，因此写入是与该电台的电台频率比较，而不是上一台的。

当电台的名称、DMR ID 和启动文字与文件不同时，写入对话框会提供**保留此电台的名称、DMR ID 和启动文字**。开启后，每台电台保留自己的这些信息，其余内容取自文件。编辑器会为下一台电台记住该选择。

对刚从原厂固件来的电台首次写入时，可能会要求**准备电台**。原厂固件的数据仍在 RadioFoundry 保存设置的区域中，在该区域被擦除之前，电台无法保存电台频率，也无法在关机后保留设置。[网页安装器](02-installing.md)在安装 RadioFoundry 时所做的备份之后会自动完成此操作。备份中保存有该数据的副本。校准不会被触碰。

内存芯片太小、放不下 RadioFoundry 设置区域的电台根本无法保存电台频率。编辑器会说明这一点，而不是去读取它（[电台](23-radios.md)列出了可能发生这种情况的型号）。

当**问题**标签页列出错误时（例如名称过长或频率无效），“写入电台”会被阻止。警告（例如频率超出电台频段，或 DMR 信道没有发射联系人）不会阻止写入。

浏览器无法访问处于 USB 网络模式的电台。此时选择**保存 > 用于 USB 网络**，并通过 TFTP 发送文件（[USB 网络](15-usb-network.md#programming-over-the-network)）。

### 编辑

| 标签页 | 内容 |
|---|---|
| 电台 | DMR ID、电台名（呼号）、启动文字、组呼和私密呼叫挂机时间 |
| 信道 | 所有信道。铅笔按钮打开完整表单：FM、DMR、扫描与功率、位置、单频中继 |
| 区域 | 区域及其信道 |
| 联系人 | 通话组和私密呼叫联系人 |
| 接收组列表 | 每个信道收听的通话组 |
| DTMF 联系人、APRS | DTMF 联系人和 APRS 配置 |
| DMR ID 数据库 | 不是联系人的 DMR ID 的名称，由 RadioID.net 构建（[见下](#dmr-id-database-and-contacts-from-radioidnet)） |
| 问题 | 错误和警告，每项都带指向该记录的链接 |

在表格中，双击单元格或直接输入即可就地编辑。点击列标题排序，在筛选中输入以缩小行范围。勾选行并选择**批量编辑**可一次设置某个字段（区域和接收列表除外，其成员在各自的对话框中编辑）。**撤销**和**重做**覆盖所有更改，包括导入。

页面会把工作用的电台频率保存在浏览器中，因此关闭或刷新页面不会丢失编辑。**新建**会重新开始。

### 文件

**打开文件**接受：

- 由编辑器、`tools/cps_client.py read` 或 TFTP 读取保存的电台频率文件（`.bin`）；
- 网页安装器的备份（`.zip`）；
- qdmr 电台频率（`.yaml`）；
- CSV 文件，每个文件一张表，或它们的 `.zip`；
- 原厂固件的电台频率，前提是编辑器能读取该电台的格式：安装器备份中的、电台数据闪存转储中的，或厂商 CPS 文件。[电台参考](23-radios.md#codeplug-files-from-the-original-firmware)列出了这些。

安装 RadioFoundry 时所做的备份仍保留原厂固件的电台频率，因为 RadioFoundry 将自己的电台频率保存在不同的布局中。编辑器能识别该电台频率并转换它：信道、区域、联系人、接收组列表、DMR ID、电台名和启动文字。之后它会列出省略的内容，例如扫描列表和被缩短的名称。带有 A、B 两个列表的区域会变成两个区域，“名称 A”和“名称 B”。写入电台前请检查结果。在你写入之前，电台上的电台频率保持原样。编辑器暂时无法打开的 CPS 文件可先用 qdmr 转换（`dmrconf decode`），再作为 YAML 打开。

**保存**会写入电台频率文件、qdmr 电台频率（`.yaml`）、当前表格的 CSV、所有表格的 CSV `.zip`，或用于 USB 网络模式的 `codeplug.bin`。

CSV 文件有带列名的表头行，并通过名称引用其他记录（信道的发射联系人、区域的信道）。先保存一张表以查看列。导入时先按编号、再按名称匹配现有记录。文件可以只包含部分列；其他列保持原值。文件中缺失的记录会被移除。编辑器无法接受的值会在导入后按行和列列出。

qdmr 文件会一次性替换信道、区域、联系人、DTMF 联系人、接收组列表、APRS 配置和电台标签页的设置，因此一次**撤销**即可还原。VFO 和 DMR ID 数据库保持不变。之后编辑器会列出更改或省略的内容，例如扫描列表、加密密钥和被缩短的名称。保存为 qdmr YAML 时会列出 qdmr 格式无法保存的内容：SFR 设置、qdmr 没有名称的功率级别，以及位置——位置会被舍入为 6 字符网格定位（约 5 公里）。工具页也可在 qdmr YAML 与电台频率文件之间转换，并将原厂固件电台频率转换为任一格式。

### DMR ID 数据库与来自 RadioID.net 的联系人

**DMR ID 数据库**标签页会从 RadioID.net 注册用户中构建数据库或私密呼叫联系人。它从以下任一来源获取用户：

- **RadioID 用户文件**：从 RadioID.net 下载 `user.csv` 并打开。任何地区、任何大小。
- **从 RadioID.net 获取**：直接获取几个州或一个小国家的用户。RadioID.net 每次请求返回 200 个用户，因此适合最多几千个用户。你自己的 RadioID API 密钥是可选的。页面把它保存在此浏览器中，仅发送给 RadioID.net。在 RadioID.net 允许来自本站的请求之前，请求会经过一个公共中继服务；密钥绝不会经过它。

然后选择：

- 地区（国家，以及州或省）；
- 呼号前缀和 DMR ID 范围；
- 每条记录显示的文本，由呼号、姓名、城市和州等字段构成；
- 文本长度（16 到 48 个字符）。

页面会预览记录，并显示数据库大小与电台剩余空间。**写入 ID 数据库**会把它放入电台频率；随后**写入电台**发送它。**添加为联系人**则把用户添加为私密呼叫联系人，跳过已是联系人的 ID。编辑器会在浏览器中记住这些选择。

联系人只保留你要呼叫的：你的通话组和少数几个私密呼叫对象。电台频率最多保存 1024 个联系人，每个都是“联系人”和通话目标选择器中的一行。其他人都交给 ID 数据库命名：不是联系人的呼叫者会显示数据库中其 ID 对应的名称。

当前固件读取**紧凑数据库**，大小约为一半，因此同样空间可容纳约两倍的名字。从 RadioID.net 刷新后，写入只发送变化的部分。编辑器在写入时选择格式：

| 电台 | 编辑器的做法 |
|---|---|
| 读取紧凑格式 | 写入它。旧格式的数据库（从电台或旧文件读取）会提示转换：一次完整写入，之后为较小的写入。拒绝后，12 小时后会再次提示 |
| 运行较旧固件 | 写入旧格式。如果名称放不下，会说明省略了多少。更新固件可腾出空间 |
| 在紧凑数据库上刷入旧固件 | 电台不显示任何名称（绝不会显示错误的名称）。编辑器下次向电台写入时，会以旧格式重新写入数据库 |

TFTP（USB 网络模式）和其他 CPS 程序使用旧格式。

## 电台从电台频率中使用什么

| 项目 | RadioFoundry 使用的字段 |
|---|---|
| 常规设置 | 你的 DMR ID。呼号（电台名，8 个字符，作为通话者别名发送）。组呼和私密呼叫的挂机时间（回复窗口） |
| 信道（最多 1024 个） | 名称、接收和发射频率、模式（FM 或 DMR）、带宽、收发亚音、功率、仅接收、色码、时隙、通话目标联系人、接收组列表（收听列表）、每信道 DMR ID、强制直通模式、发射超时（电台默认：电台自身的设置，[发射超时](08-fm.md#transmit-timeout)）、通话者别名、区域扫描跳过、允许 VOX、无提示音、无省电 |
| 区域 | 名称和信道列表。没有区域时，电台显示一个包含所有信道的区域 |
| 联系人（最多 1024 个） | 名称、DMR ID 或通话组、私密或组呼、时隙覆盖 |
| 接收组列表 | 每个信道收听的通话组 |
| DMR ID 数据库 | 不是联系人的 DMR ID 的名称，显示在接收屏幕上 |
| VFO A | VFO 的频率和设置，下次重启后读取 |
| 启动文字 | 启动画面上的两行 |

电台保持电台频率的其他部分不变（启动图像、DTMF 联系人等），因此编辑器和 qdmr 能读回它们写入的内容，但 RadioFoundry 不会对这些部分起作用。

在电台上所做的更改（长按 **OK** 保存的信道、永久通话目标）会写入同一份电台频率，因此下次读取时可见。

电台频率目前还不能设置：

- 加密密钥（[DMR](09-dmr.md#privacy)）。
- RadioFoundry 自身的设置（[设置](17-settings.md)）：它们与电台频率分开保存。电台频率中的快捷键分配会被忽略。
- 紧急、ARS 和文本消息格式。
- qdmr 中的 SFR 设置。电台频率编辑器会在每个信道上设置它们。

## 用 qdmr 编程

电台通过兼容层使用 qdmr 开源固件驱动的协议，并以 qdmr 写入的布局保存电台频率。

1. 正常开机并连接 USB 线。电台会显示为一个 USB 串口。
2. 在 qdmr 中从电台读取电台频率。qdmr 通过 RadioFoundry 报告的电台类型来识别电台。[电台参考](23-radios.md#programming)列出了每款电台的类型和 qdmr 驱动。
3. 编辑电台频率并写入电台。
4. 写入后，电台重启并使用新的电台频率。

电台在传输期间保持自己的屏幕。电台频率所在位置无法被 qdmr 驱动写入、或没有 USB 口的电台需要其他途径。[电台参考](23-radios.md#programming)会说明是哪种。

## 备份

更改前先读取并保存电台频率：编辑器中的**保存 > 电台频率文件（.bin）**，或在 qdmr 中保存。原始备份也可以：通过串口执行 `tools/cps_client.py read backup.bin` 和 `tools/cps_client.py write backup.bin`，或在 USB 网络模式下使用 TFTP（[USB 网络](15-usb-network.md#programming-over-the-network)）。

安装时迁移原厂电台频率，见[从原厂固件迁移](README.md#moving-from-the-stock-firmware)。

## 限制与说明

- 当电台的设置区域保存着其他固件的数据时，写入会被拒绝。见[故障排查](20-troubleshooting.md#settings-are-not-kept)中的“设置未保存”。
- 校准区域只接受写入其自身的字节。不要用 CPS 编辑校准。
