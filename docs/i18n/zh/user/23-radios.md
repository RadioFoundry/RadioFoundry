## 各电台的双守候

[双守候](12-scan.md#dual-watch)收听两个信道 A 和 B。目前构建的所有电台都只有一个接收机，因此在每款电台上都是伪双守候：电台在 A 和 B 之间交替。一个信道上的呼叫可能在电台位于另一信道时被错过。有两个接收机的电台能同时听到两者并在各自信道上显示呼叫。UI 已为此做好准备（`ui_svc_receivers()` 大于 1），但尚无电台报告两个接收机，核心也未使用它们。

| 电台 | 双守候 | 启动 | 切换 A / B |
|---|---|---|---|
| DM-1701 | 伪双守候，单接收机。核心在同一区域两个信道间的交替已在空中验证；新的双守候（任意区域、VFO、屏幕）尚未 | **\***、**7**，或长按 **SK2** | 短按 **SK2**、**#**、**1** |
| MD-380 | 伪双守候，单接收机。未在空中验证 | **\***、**7**，或长按 **SK2** | 短按 **SK2**、**#**、**1** |
| MD-UV380 | 伪双守候，单接收机（两个频段共用一个 AT1846S）。未在空中验证 | **\***、**7**，或长按 **SK2** | 短按 **SK2**、**#**、**1** |
| DM-32UV | 伪双守候，单接收机。未在空中验证（本电台的扫描也尚未验证） | **\***、**7**，或长按 **SK2** | 短按 **SK2**、**左** / **右** |
| DB25-D PRO | 伪双守候，单接收机。未在空中验证。其第二颗 BK4819 芯片是接收链的本振，不是第二接收机 | 长按 **TONE/T.SEL** 键 | 短按 **TONE/T.SEL** |
| DM-1801 Pro | 伪双守候，单接收机。未在空中验证 | 长按 **A/B** 键、**\***、**7**，或长按 **SK2** | 短按 **A/B** 键或 **SK2**、**左** / **右** |

长按 **SK2** 在所有有 SK2 的电台上是双守候，DB25-D PRO 上则是长按音调键。短按 **SK2**（DB25-D PRO 为音调键）切换 A / B，双守候关闭时提示“请先开启双守候”。DM-1801 Pro 的 A/B 键两者兼有：短按切换 A / B，长按启动和停止双守候。在该机上区域在**左** / **右**上，或在区域菜单中。

A 和 B 可以是任意区域的任意信道，或 VFO（[核心的实现方式](../spec/radio-features.md#21-dual-watch)）。此双守候尚未在任何电台上经空中验证。

Anytone AT-D578UV 是双接收机场景的目标机型：其硬件有两颗接收芯片（[Anytone 硬件说明](../spec/hardware-anytone.md)）。RadioFoundry 没有它的板级支持，因此不受支持。

## 从电脑设置音量

`rfoundry_debug.py volume` 打印电台使用的音量及其来源。`rfoundry_debug.py volume 12` 设置 16 档中的第 12 档（0 为静音），`rfoundry_debug.py volume knob` 交还旋钮控制（经 DM-32UV 的串口线时加 `--port /dev/ttyUSB1` 或你线缆的端口）。具体行为取决于电台：

| 电台 | 从电脑设置音量 |
|---|---|
| DM-1701 | 可以。电台读取旋钮并自行设置音频增益，因此电脑的电平会取代旋钮，直到你发送 `knob` 或重启电台。不会被保存 |
| MD-380 | 不行。旋钮直接作用于音频通路；电台回答“不支持” |
| MD-UV380 | 可以，与 DM-1701 相同（同一音频通路）。未在电台上验证 |
| DM-32UV | 不行。旋钮直接作用于音频放大器；电台回答“不支持” |
| DB25-D PRO | 可以。没有旋钮：电平就是电台自身的音量设置，因此电脑更改该设置并会保存，如同你在电台上设置。`knob` 恢复默认（第 8 档） |

[电台频率编辑器](04-programming.md#the-codeplug-editor)可为以下所有电台编程。qdmr 需要端口上有电台，且使用其驱动认识的地址。

| 电台 | 线缆 | qdmr |
|---|---|---|
| DM-1701 | USB | 电台类型 8（另一种屏幕变体为 10）。使用 qdmr 的 UV380 系列驱动 |
| MD-380 | USB | 电台类型 7 |
| DM-32UV | 编程线（无 USB） | 无法直接编程。RadioFoundry 把电台频率保存在电台数据闪存 7 MB 处，因此 qdmr 驱动使用的地址落在原厂区域，RadioFoundry 拒绝在那里写入。请在 qdmr 中编辑电台频率，保存为 YAML，再用 `dm32_migrate.py restore --yaml FILE` 写入（[从原厂 DM-32UV 固件迁移](19-moving-from-stock-dm32.md)），它会加上偏移。电台目前报告类型 6（MD-UV380） |
| DB25-D PRO | 编程线，K1 插孔（[见下](#programming-the-db25-d-pro-over-the-cable)） | 报告类型 6。电台频率位于 DM-1701 的地址，因此 qdmr 的 MD-UV380 驱动应该可用。未尝试 |
| DM-1801 Pro | 编程线 | 未列出 |

| 级别 | 低于 |
|---|---|
| 低 | 6.2 V |
| 严重 | 6.0 V |

### DM-1701 电源开关

电源开关在音量旋钮上。顺时针转过“咔嗒”一声开机，逆时针转到“咔嗒”一声关机。开关切断电池检测线，因此电台把低于 5.5 V 的读数视为“关机”，会完成当前工作、保存并自行断电。深度放电的电池读数相同，电台也会关机。

旋钮仍开启时电台能否自行断电（自动关机）尚未验证。若不能，电台会在 2 秒后恢复并显示“无法关机 / 请关闭旋钮”。

### DM-1701 显示屏

160 x 128 彩色屏，顶部 8 行隐藏：可见 160 x 120。本手册中的截图即此尺寸。

### DM-1701 缺少什么

- 出厂无 GPS。LRRP 位置请求得到“无定位”。APRS 位置来自电脑或固定位置。若自行加装 GPS 模块，请把其 NMEA 输出接到 PA10（STM32 引脚 69）。电台会在启动时发现它（[hardware-dm1701.md 14.2](../spec/hardware-dm1701.md#142-gps-module)）。
- APRS 接收需要静噪打开：电台只能听到强到足以打开静噪的分组，弱分组听不到。
- 没有 APRS iGate（把听到的分组传给 APRS-IS）：flash 空间还不够。
- 没有振动马达：镜像中没有**设置 > 声音 > 振动**。

## TYT MD-380

- APRS 收听期间，APRS 频率上的 FM 经另一条音频通路播放，声音可能不同。
- 航空波段和调频广播接收（[航空波段与调频广播](07-channels-zones-vfo.md#air-band-and-fm-broadcast)）已构建但尚未在电台上验证。广播覆盖 65 到 108 MHz。

- 音频互联（USRP）只承载 DMR：来自处理器的 FM 发射通路尚未编写。
- 发射期间没有提示音，包括允许发射提示音：电台的提示音通路会把它们送上空中。发射结束时仍在播放的提示音会从那时起被听到。
- 以 dBm 表示的信号强度未校准：强信号读数偏高。
- 没有振动提醒：RadioFoundry 不在其上驱动振动马达，镜像中也没有**设置 > 声音 > 振动**。

| DBB | DB25-D PRO：两颗 BK4819（2024 年起） | 支持 |
| D64 | FD6818 收发器，0x7813 本振（2021 到 2023） | 测试中：同一镜像，未在此硬件上测试 |

### 安装 DB25-D PRO

网站上的电台编程工具通过编程线（K1 插孔）安装和更新本电台。没有 rfoundry 途径。

| 电台运行 | 电台编程工具的做法 |
|---|---|
| 原厂固件（909E.DBB.EARSAB.018 或 .020） | 通过原厂固件的诊断控制台把电台切换到更新模式：约 4 分钟，无需按键，也不向电台内存写入任何内容。然后备份整个 2 MB 程序存储器（约一分钟）、安装并重启电台，与运行 RadioFoundry 的电台相同。版本为 020 或某个 018 构建（2024-05-09 或之后）时，语音编解码器取自备份。其他版本时备份仍然完整；工具会说明，并要求厂商的 018 原厂文件，其编解码器适用于所有版本 |
| 其他版本的原厂固件，或无法启动的电台 | 通过原厂加载器的厂商更新模式安装：关机，按住 P1 并按电源。红色 LED 点亮，显示保持空白。此方式不做备份。加载器本身绝不会被写入 |
| RadioFoundry | 经调试链路把加载器交接到 RAM 中（无需按键，无需断电），只写入变化的扇区并重启电台。程序存储器备份可选 |
| 不应答的 RadioFoundry | “开机恢复”：第一阶段在每次开机时应答半秒，电台编程工具此时载入加载器 |

每次开机都显示白色背光屏和常亮红灯、且未按 P1 的电台，因应用程序缺失或不完整而卡在厂商更新模式。它不需要按键：工具会向加载器发一个只读问题，说明电台处于更新模式并安装。不会为此写入任何内容。

线缆上无任何应答时，故障排查会提供“在厂商更新模式中重新安装”，恢复也会以同样方式通过厂商更新模式写回备份。经控制台或 RadioFoundry 恢复是常规途径；两者都不应答时，厂商更新模式是回退方式。

电台 NAND 存储器中的信道和联系人不在电台编程工具的备份范围内；请用厂商编程软件或 `tools/cps_client.py` 备份（见下文）。

### DB25-D PRO 功率与供电

两档：L 和 H（标称 20 W）。在 RadioFoundry 能读取其功率校准之前，电台拒绝发射。

电台使用 13.8 V 电源，没有电池。状态行不显示电池图标或百分比，工具中没有电池页面，设置 > 电源中没有省电或低电量提示。RadioFoundry 不读取电源电压，因此没有任何提示。

### DB25-D PRO 显示屏

1.77 英寸彩色屏，160 x 128。

没有音量旋钮。按 **VOL/SQL**，转动前面板旋钮（或按上、下）把音量从 0（静音）调到 16，然后按 OK 或返回，或等待 3 秒关闭。屏幕以 16 段条上的大号数字显示档位。该电平也在设置 > 声音 > 音量中。RadioFoundry 在接收芯片的音频输出处设置并保留它。较早的 10 档构建保存的值会换算迁移（第 5 档变为 8，第 10 档变为 16）。各档尚未校准：每档有多响尚未实测，因此需要自行调整。

### 经线缆为 DB25-D PRO 编程

电台频率（信道、区域、联系人、电台名和 DMR ID）经侧面 K1 插孔的编程线、通过 USB 串口适配器（115200 波特）读写。电台没有 USB 口。电台频率保存在与 DM-1701 相同的地址，因此 `tools/cps_client.py` 无需偏移，qdmr 的 MD-UV380 驱动应该可用（电台报告类型 6；尚未尝试）。该工具需要 `pyserial`。示例使用 `/dev/ttyUSB1`：

```
python3 tools/cps_client.py --port /dev/ttyUSB1 info                  # 类型 6、构建日期、闪存大小
python3 tools/cps_client.py --port /dev/ttyUSB1 read backup.bin       # 约 20 秒
python3 tools/cps_client.py --port /dev/ttyUSB1 write backup.bin      # 然后电台重启
python3 tools/cps_client.py --port /dev/ttyUSB1 verify backup.bin     # "match"
```

请先备份。未存储任何内容的电台显示内置单工 FM 信道，读取会返回空白（0xFF）字节。要把测试信道放上去，请读取电台频率、把它们加入文件、再写回：

```
python3 tools/cps_client.py --port /dev/ttyUSB1 read cp.bin
python3 tools/cps_client.py test-channels cp.bin --rx 461.4625 --tg 201 --cc 2 --ts 1 --id 1234567 --call N0CALL
python3 tools/cps_client.py --port /dev/ttyUSB1 write cp.bin
python3 tools/cps_client.py --port /dev/ttyUSB1 verify cp.bin
```

`test-channels` 把信道 1 设为 FM 信道（12.5 kHz、单工、无亚音），信道 2 设为同频率的 DMR 信道（色码 2、时隙 1、通话目标组 201），区域 1 包含两者。它会替换这些信道、第一个联系人和第一个区域，文件中的其他内容保持不变。DMR 信道需要 `CONFIG_DMR=y` 的构建（默认）；否则电台只列出其 FM 信道。`verify` 比较工具传输的区域。写入会整块替换 4 KB 扇区，每个扇区一步完成：断电或拔线会让每个扇区保持原样或完全变为文件内容，绝不会一半一半。电台自身的设置和出厂校准绝不会被编程工具写入。当电台存储中存有其他固件的数据时（诊断页显示 `nst foreign`，见下文），写入会被拒绝。

### DB25-D PRO 目前缺少什么

GPS 模块在启动时检查：若 5 秒内应答，电台就有 GPS（APRS 位置源和位置设置），否则隐藏 GPS 功能。仅在**设置 > 位置 > GPS** 开启时供电。电台能听到该模块（有效 NMEA 语句）；户外定位尚未验证。

构建包含 MMDVM 热点（单工，经编程线）和经 PPP 的 IP 网络及其服务，与 DM-32UV 一样，均已在电台验证。DMR VFO 在此电台也可用（收发已验证）。没有单频中继和分离双工热点角色，也没有 APRS 接收或 iGate（电台不给核心提供 FM 接收音频）。尚无 VOX：读取麦克风电平的板级代码尚未编写。DMR 语音需要来自受支持原厂文件的编解码器（硬件说明第 8 节），扬声器的 DMR 音频尚未试听。经线缆编程已在一台电台上运行。设置会跨关机保留，保存在电台内存中原本未使用的一部分。若 RadioFoundry 在那里发现不是它写入的数据，会保持不动且不保存设置（诊断页显示 `nst foreign`）。仅支持 PRO（两颗 BK4819 接收芯片），不支持较早批次。

## 宝锋 DM-1801 Pro

136-174 和 400-470 MHz 手持台，带键盘、方向键和 128 x 64 单色屏。FM 和 DMR 已在空中验证：语音呼叫双向、CTCSS 和 DCS、文本消息和其他 DMR 数据，以及热点模式。

构建通过电台自带的更新模式写入，因此原厂加载器保留，原厂固件也能以同样方式回退：关机，按住 **PTT** 和 **SK1**，开机，然后经编程线运行 `tools/serial_loader.py --model dm1801pro IMAGE`。线缆插头会关闭内置扬声器和麦克风；要听电台或通话请拔下它。

设置 > 通话与收听 > 麦克风增益在此电台上设置 FM 和 DMR 的麦克风电平。

`rfoundry flash IMAGE --board dm1801pro` 经线缆做同样的事，并自行选择进入方式：

| 电台运行 | rfoundry |
|---|---|
| 使用 `CONFIG_STUB_ENTRY=y` 构建的 RadioFoundry | 从 RadioFoundry 进入加载器（屏幕显示“PC 加载器已连接”），只写入变化的部分并重启电台。无需按键。电台中的编解码器保留 |
| 其他任何情况 | 要求你把电台置于更新模式（开机时 PTT 和 SK1）。更新模式会擦除编解码器，因此镜像必须携带它（构建的 `rfoundry_dm1801pro_codec.bin`），或提供 `--stock` 及本电台的程序闪存读取（`stub/stubtool.py PORT --progmem FILE`） |

`--route stub` 或 `--route bootloader` 可手动选择，`--dry-run` 显示计划而不写入。rfoundry 的两条途径都尚未刷写过电台；`tools/serial_loader.py` 和 `stub/stubtool.py` 已刷写过。

在网页安装器中，线缆无法准备电台时，**使用厂商更新模式**会通过同一更新模式安装（开机时 PTT 和 SK1）。本电台没有原厂固件文件，因此编解码器来自其程序存储器备份（`program-memory.bin`，或安装器在首次安装前保存的备份 `.zip`）或浏览器保留的编解码器。尚未在 DM-1801 Pro 上从网页安装器测试。

### DM-1801 Pro 功率与显示屏

三档功率：L、M、H，即低、中、高。在 RadioFoundry 能读取其出厂校准之前，电台拒绝发射。电池读数按一台电台上的一次测量换算。屏幕为单色；背光只有开或关。电台会为消息、呼叫提示和紧急振动（**设置 > 声音 > 振动**）。

### DM-1801 Pro 目前缺少什么

- 分离双工中继：每一半都用一台电台在空中通过（发射半的带 CACH 的出向和主机送入的语音呼叫，接收半的时隙标签）。尚未测试真正的一对电台。
- APRS 接收未验证。APRS 发送在 FM 和经 DMR 上可用。
- VHF 发射未在空中验证。UHF 收发和两个频段的接收均可用。
- VOX 未验证。RadioFoundry 现已从麦克风的数字音频读取麦克风电平，但尚未在电台上尝试。
- 航空波段和调频广播接收（[航空波段与调频广播](07-channels-zones-vfo.md#air-band-and-fm-broadcast)）已构建但尚未在电台上验证。广播覆盖 65 到 108 MHz。
